What is a Message?

When a Producer sends data to a queue, that data is called a Message.
Every message has two parts:
Message
│
├── Header (Metadata — info about the message)
│
└── Body (Payload — actual data to process)
Think of it like a courier parcel —
the shipping label is the Header,
the item inside is the Body.
02 / 09

The Parcel Analogy

Imagine you're sending a package through a courier service.
📋 Outside Label = Header
• Tracking Number
• Sender Name
• Receiver Address
• Delivery Priority
• Package Type
The courier reads this to deliver it.
📦 Inside Box = Body
• The actual laptop
• Charger & accessories
• Invoice / receipt
The receiver opens this and uses it.
The Queue/Broker reads the Header (label).
The Consumer reads the Body (contents).
03 / 09

6 Key Header Fields

01 · Message ID
Unique ID for every message. Helps with tracking and duplicate detection.
MSG-1001
02 · Timestamp
When the message was created. Used for monitoring and TTL checks.
2026-08-08T10:30
03 · Message Type
What kind of message it is. Consumer decides action based on this.
SEND_EMAIL
04 · Routing Key
Tells the broker which queue to deliver this message to.
email.queue
05 · Priority
How urgent the message is. HIGH priority gets processed first.
HIGH / LOW
06 · Correlation ID
Links multiple messages from the same request in distributed systems.
REQ-4567
04 / 09

Body = Payload

The Body carries the actual business data that the Consumer will use to do its job.

Example Body

{
  "name": "Rahim",
  "email": "rahim@gmail.com",
  "subject": "Welcome",
  "message": "Thanks for joining."
}

Supported Formats

JSON — most common format
Plain Text — simple strings
XML — structured markup
Binary — images, video, files

06 / 09

Header vs Body

They serve different purposes for different parts of the system.
Header (Metadata)
Used by the Queue / Broker
Contains routing information
Has priority level
Stores message type
Includes tracking IDs
Body (Payload)
Used by the Consumer
Contains business data
Has user information
Stores email / order / payment data
Actual content to process
The Broker doesn't need to know what's in the email.
It only needs the routing key, priority, and queue name.
07 / 09

Best Practices &
Common Mistakes

✓
Keep your Header small — only metadata, never business data.
✓
Put actual business data in the Body — email content, order details, etc.
✓
Use JSON format — it's the most common and readable payload format.
✓
Always include a unique Message ID and Timestamp in every message.
✓
Use Correlation ID in microservices to trace related messages.
✗
Don't dump entire business data into the Header.
✗
Don't skip Message Type — the consumer needs it to know what to do.
✗
Don't skip Message ID — you can't track or debug without it.
